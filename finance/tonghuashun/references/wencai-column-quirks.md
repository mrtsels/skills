# wencai 列名编码日期实测记录

## 问题

wencai_nlp 返回的 DataFrame 列名会**将 NLP 查询的时间上下文编码进列名**，导致：
1. 按直觉取的列名（如 `成交量环比增长率[20260710]`）可能根本不存在
2. 实际列名使用复杂的花括号编码（如 `{(}{(}成交量[20260710]{-}成交量[20260709]{)}{/}成交量[20260709]{)}`）
3. 列的顺序不固定，同一查询在不同日期可能产生不同列序

## 实测：成交量放大选股

**查询语句：**
```
上周五成交量较前一日放大超过2倍，总市值小于100亿，上周五涨幅大于3%，非ST，非北交所
```

**返回列名（按位置）：**

| 位置 | 列名 | 含义 |
|------|------|------|
| 0 | `{(}{(}成交量[20260710]{-}成交量[20260709]{)}{/}成交量[20260709]{)}` | 成交量环比变化率（小数，如 2.02 = +202%） |
| 1 | `{(}成交量[20260710]{-}成交量[20260709]{)}` | 成交量差值 |
| 2 | `总市值[20260709]` | 上周四收盘市值 |
| 3 | `成交量[20260709]` | 上周四成交量 |
| 4 | `成交量[20260710]` | 上周五成交量 |
| 5 | `最新价` | 当前价格 |
| 6 | `最新涨跌幅` | 今日涨跌幅（盘前 = 开盘价变幅） |
| 7 | `涨跌幅:前复权[20260710]` | 上周五收盘涨跌幅 |
| 8 | `股票代码` | 格式如 `300933.SZ` |
| 9 | `股票市场类型` | 逗号分隔的市场分类 |
| 10 | `股票简称` | 中文名称 |

## 安全处理模式

```python
# 永远先 dump 列名
resp = ths.wencai_nlp("你的查询")
df = resp.df
cols = df.columns.tolist()
print("DEBUG cols:", cols)

# 依位置取字段（推荐——列序比列名更稳定）
CODE_COL  = next(i for i, c in enumerate(cols) if '代码' in c)
NAME_COL  = next(i for i, c in enumerate(cols) if '简称' in c)
PRICE_COL = next(i for i, c in enumerate(cols) if c == '最新价')
MCAP_COL  = next(i for i, c in enumerate(cols) if '总市值' in c)
VOL_CHG   = cols[0]  # 第一列通常是成交量环比
CHG_COL   = next(i for i, c in enumerate(cols) if '涨跌幅' in c and '前复权' in c)
```

## 关联陷阱

- 不要假设 `成交量环比增长率[YYYYMMDD]` 这个列名存在
- 如果查询涉及日期比较，所有带日期的列都会编码具体日期，无法提前预测格式
- Windows 环境还可能叠加 GBK 乱码（列名变成 `ﾽﾽﾽﾽﾽ`）— 参见主 skill 的 GBK pitfall
