# TASK.md 文档规范

## 结构规则

1. **子阶段必须在其父阶段内部** — Phase 4.8/4.9 必须在 Phase 4 标题下, 不能放在文件末尾
2. **标题带状态标记** — 完成加 ✅, 未开始 ⬜, 部分完成 🔶
3. **不允许 :** 标题打 ✅ 但子项还是 [ ] — 必须全完成或标题也不打勾
## 格式统一 — 同级条目用同一种格式

**整个文档同一层级必须用一种格式，不能混搭。** 要么全 `- [x]` 列表，要么全表格。

反例（被用户批评过的）:
```
## Phase 1: ...  ✅
- [x] 1.1 做某事

## Phase 5: ...  (无✅)
| 5A | 东西 | 其他 |
- [x] 5A.1 ...
```

正例：
```
## Phase 5: 集成测试 ✅
- [x] **5A.1** 数据管线
- [x] **5A.2** 图构建
(全 `- [x]` 列表，Phase 5 标题带 ✅)

## Phase 6: 性能测试 ✅
| Benchmark | Metrics | Result |
|-----------|---------|--------|
(全表格，Phase 6 标题带 ✅)
```

**什么时候用表格，什么时候用列表:**
- 任务清单: `- [x] **N.x** 描述` 列表
- 实验结果/指标对比/状态摘要: 表格
- 一个文档内两种格式交替出现是 OK 的，只要 **同一小节内** 不混

5. **不可有孤立文字** — 每条 checkbox 后的说明性文字必须在该条下方缩进, 不能悬空

## Checkbox 规则

- `[x]` = 已完成并验证
- `[ ]` = 未开始
- 半完成的任务不会出现在 TASK.md, 而是在 conversations 中追踪

## 表格使用

- 仅用于: 实验结果对比、状态汇总、配置列表
- 不用于: 任务列表、子阶段描述（用 `- [x]` 列表）

## 内容组织顺序

1. Header + 阶段进度条
2. Phase 1 → Phase 2 → ... → Phase N (按数字顺序)
3. 方法论对照表
4. 执行原则
5. Stretch Goals

不允许: 在 Phase 9 后面出现 Phase 4.8/4.9 这样的回溯追加。

## 重新编号 / 改顺序操作 (十字引同步)

当需要调整 Phase 顺序或重新编号时，除了修改 TASK.md 本身，还必须同步检查以下文件中的 Phase 引用：

1. **AGENTS.md** — 可能包含 `Remaining: ... Phase N (web demo)` 等摘要行，这些行容易过时
2. **CLAUDE.md** / `.cursorrules` — 同样可能引用了旧的 Phase 编号或阶段描述

**操作步骤：**
- 先修改 TASK.md: 进度条 → 各 Phase 标题 → 子项编号 → 所有内链
- 搜索 `Phase 1[1-9]` 和 `Phase 2[0-9]` 跨文档匹配，确认无遗漏
- 特别检查 AGENTS 和 CLAUDE 中的「Current State」或「Remaining」摘要块
- 提交时 commit message 注明 `docs: renumber phases N→M across all dev docs`

**陷阱：** AGENTS.md 的摘要行是静态文本，不会随 TASK.md 自动更新。重编号后必须手动找到并修改这些摘要，否则下次 agent 加载时会读到过时的 Phase 号（如 "Phase 5: web demo" 实际上是 Phase 11）并产生误导。
